# Linux Kernel Concepts

## Kernel vs User Space

**Kernel Space:**
- Core OS, device drivers
- Full hardware access
- Privileged operations
- Ring 0 (x86/x64) / EL1 (ARM)

**User Space:**
- Applications run here
- No direct hardware access
- Must use system calls
- Ring 3 (x86/x64) / EL0 (ARM)

```
User Space:  [Your App] → system call → Kernel
Kernel:      [Process] [Memory] [Drivers] [Filesystem]
Hardware:    [CPU] [RAM] [Disk] [Network]
```

## System Calls

**Bridge between user space and kernel.**

```c
// User space
printf("hello");

// Becomes system call
write(1, "hello", 5);  // syscall to kernel

// Kernel executes
// Returns to user space
```

## Process States

```
R - Running (executing or ready)
S - Sleeping (waiting, interruptible)
D - Disk sleep (uninterruptible, waiting I/O)
Z - Zombie (finished, waiting for parent)
T - Stopped (paused by signal)
```

**Check:**
```bash
ps aux  # See STAT column
```

## Kernel Threads

**Processes run by kernel, not users.**

```bash
ps aux | grep '^\[.*\]'
# [kworker/*]  - kernel workers
# [ksoftirqd]  - software interrupts
# [kthreadd]   - creates other kernel threads
```

**Characteristics:**
- Shown in `[brackets]` in ps
- PPID = 0 or 2
- Can't kill with regular signals
- Run in kernel space

## Memory Management

**Virtual memory:**
- Each process sees own address space
- Kernel maps virtual → physical
- Pages loaded on demand

**Key concepts:**
- Page = 4KB memory unit
- Page fault = access not-loaded page (normal)
- Swap = disk used as RAM extension (bad for performance)

## Context Switching

**Kernel switches between processes:**
1. Save current process state
2. Load next process state
3. Resume execution

**Cost:** High context switches = performance issue

```bash
vmstat 1
# cs column = context switches per second
```

## /proc Filesystem

**Virtual filesystem exposing kernel data.**

```bash
cat /proc/cpuinfo      # CPU info
cat /proc/meminfo      # Memory stats
ls /proc/123/          # Process 123 info
cat /proc/123/status   # Process details
```

Not real files - generated by kernel on read.

## Kernel Ring Buffer

**Circular buffer for kernel messages.**

```bash
dmesg                  # View kernel messages
dmesg -w               # Follow new messages
dmesg | grep -i error  # Find errors
```

**Contains:**
- Boot messages
- Hardware detection
- Driver errors
- OOM killer events

## Interrupts

**Hardware signals to kernel:**
- Keyboard press
- Network packet arrives
- Timer tick
- Disk I/O complete

**Check:**
```bash
cat /proc/interrupts
```

## Kernel Modules

**Loadable kernel code (drivers).**

```bash
lsmod                  # List loaded modules
modprobe module_name   # Load module
modinfo module_name    # Module info
```

## CPU Protection Levels

**x86/x64 Architecture:**
- Ring 0 = Kernel (privileged)
- Ring 1-2 = Rarely used
- Ring 3 = User applications

**ARM Architecture:**
- EL0 = User applications
- EL1 = Kernel
- EL2 = Hypervisor (virtualization)
- EL3 = Secure monitor (TrustZone)

**Purpose:** Prevent user apps from crashing system or accessing hardware directly.

**System call:** Ring 3/EL0 → Ring 0/EL1 → back to Ring 3/EL0

## Key Files

```
/proc/        - Process/system info
/sys/         - Hardware/device info
/dev/         - Device files
/boot/        - Kernel images
```

## Interview Tips

**Common questions:**
- "Process stuck in D state" → Waiting uninterruptible I/O
- "High context switches" → Too many threads or lock contention
- "Kernel panic" → Kernel crash, requires reboot
- "OOM killer" → Kernel killed process for memory

**Understanding kernel helps explain:**
- Why some operations need root
- Why D-state processes can't be killed
- How system calls work
- Performance bottlenecks
